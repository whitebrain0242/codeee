# Redis

## 使用

### Command

#### 🔌 通用命令 (Connection & Server)

与具体数据无关，用于管理连接或获取服务器信息。

-   **PING**：测试连接是否活跃，正常返回 `PONG`。
-   **SELECT**：切换数据库（默认索引从 0 开始）。
-   **ECHO**：打印传入的字符串。
-   **QUIT / EXIT**：关闭当前连接。
-   **INFO**：获取 Redis 服务器的各种统计信息。

#### 🔑 键 (Key) 操作命令

用于管理 Redis 中的任意键。

-   **DEL**：删除一个或多个键。
-   **EXISTS**：检查一个或多个键是否存在。
-   **EXPIRE**：为键设置过期时间（秒）。
-   **TTL**：查看键的剩余生存时间（秒）。
-   **TYPE**：返回键所存储值的数据类型。
-   **KEYS / SCAN**：查找匹配模式的键（生产环境建议用 `SCAN` 代替 `KEYS`）。

#### 📦 数据结构操作命令

这是 Redis 最核心的部分，命令根据存储的数据类型（String、Hash、List、Set、ZSet）分类。

**1. 字符串 (String)**
最基础的类型，适合缓存、计数器等。

-   **SET**：设置键值，支持 `EX`（秒）、`NX`（不存在时设置）等选项。
-   **GET**：获取键值。
-   **INCR / DECR**：将值原子性增/减 1。
-   **MSET / MGET**：批量设置或获取多个键值。

**2. 哈希 (Hash)**
适合存储对象，如用户信息。

-   **HSET / HGET**：设置或获取哈希表中字段的值。
-   **HMSET / HMGET**：批量设置或获取多个字段的值。
-   **HGETALL**：获取哈希表中所有字段和值。
-   **HINCRBY**：将字段值原子性增加指定整数。

**3. 列表 (List)**
有序的字符串列表，适合消息队列、最新消息列表等。

-   **LPUSH / RPUSH**：从列表头部（左）或尾部（右）插入元素。
-   **LPOP / RPOP**：从列表头部或尾部移除并返回元素。
-   **LRANGE**：获取列表指定范围的元素。

**4. 集合 (Set)**
无序且唯一的字符串集合，适合标签、共同好友等。

-   **SADD**：向集合添加一个或多个成员。
-   **SMEMBERS**：返回集合中所有成员。
-   **SISMEMBER**：判断成员是否在集合中。

**5. 有序集合 (Sorted Set)**
每个元素关联一个分数，并按分数排序，适合排行榜等。

-   **ZADD**：添加成员并指定分数。
-   **ZRANGE**：按分数从小到大返回指定范围的成员。

#### 🚀 高级功能命令

-   **事务 (Transaction)**：`MULTI`, `EXEC`, `DISCARD`。
-   **Lua 脚本**：`EVAL`, `EVALSHA`。
-   **发布/订阅 (Pub/Sub)**：`PUBLISH`, `SUBSCRIBE`。
-   **持久化**：`SAVE`, `BGSAVE`。
-   **集群管理**：`CLUSTER`

### ReplyType

| 常量                      | 数值 | 描述                                                         | 对应数据结构字段                                             |
| :------------------------ | :--- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **`REDIS_REPLY_STRING`**  | 1    | **批量字符串** (Bulk String)。最常见的类型，如 `GET` 命令的返回值。 | `reply->str` (char*) 和 `reply->len` (size_t)                |
| **`REDIS_REPLY_ARRAY`**   | 2    | **数组**。用于返回多个元素，如 `LRANGE`、`HGETALL` 命令。    | `reply->elements` (size_t) 和 `reply->element` (redisReply**) |
| **`REDIS_REPLY_INTEGER`** | 3    | **整数**。用于返回数字，如 `INCR`、`SCARD` 命令。            | `reply->integer` (long long)                                 |
| **`REDIS_REPLY_NIL`**     | 4    | **空值**。表示返回的结果不存在，如 `GET` 一个不存在的 key。  | 无数据，检查此类型以处理空值                                 |
| **`REDIS_REPLY_STATUS`**  | 5    | **状态回复**。通常表示命令执行成功，如 `SET`、`PING` 命令。  | `reply->str` (char*) 和 `reply->len` (size_t)，内容通常是 "OK" 或 "PONG" |
| **`REDIS_REPLY_ERROR`**   | 6    | **错误回复**。表示命令执行出错，如密码错误、操作了错误的数据类型等。 | `reply->str` (char*) 和 `reply->len` (size_t)，内容是具体的错误信息 |



### ChatServer的存活检验

#### 为什么选择redis？

##### 原子性

需求：当多个服务器争抢要为用户设置在线状态的时候，必须保证只有一个成功

Redis提供`SET NX`（不存在才设置）命令，和LUA脚本“读-比较-写”原子操作，完美解决并发竞争

##### 内置TTL（自动过期）

需求：服务器崩溃，在线状态必须自动消失

Redis：支持 `EXPIRE` 和 `SET NX EX`，这是键自带的属性，毫秒级自动淘汰

##### 键值对

需求：业务层只需要知道谁属于谁，不需要外键，事务回滚

Redis：相当于一个巨大的哈希表，get set都很快

但是如果是MYSQL,为了键值对，可能要建表，建立索引

##### 速度快

Redis是基于内存的，所以读写延迟都很快
